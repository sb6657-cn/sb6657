# AI 实施计划规范

这份规范定义：跨多次对话、需要按步骤推进的大改动，如何在仓库里写成计划、如何恢复进度、一次做多大。

它不是设计文档模板，也不是更新日志。短任务（单文件 bug、文案、一次性能修补）不要为此建计划。

## 什么时候必须建计划

同时满足下面两条就建：

1. 预估要 **2 次以上独立对话** 才能做完，或会改 **5 个以上** 业务文件。
2. 中途换模型 / 换会话后，不能靠聊天记录可靠恢复「做到哪了、下一步碰哪些文件」。

典型例子：全站主题、跨页面的信息架构调整、把巨型页面按业务拆分并保持行为不变。

不适合建计划：改一个组件样式、修一个接口字段、只改文档。

## 存放位置和命名

| 路径 | 用途 |
| --- | --- |
| `docs/ai-plans/README.md` | 本规范，不要在这里写具体业务计划 |
| `docs/ai-plans/<slug>.md` | 一份进行中或已归档的计划 |

- 目录名和文件名用小写英文短横线，例如 `dark-mode.md`。
- `slug` 要稳定，创建后不要为了好看改名；进度全靠这个文件路径。
- 一份计划一个文件。不要把多个大改动塞进同一份。
- 不要把计划写进 `AGENTS.md` 或 `AI_GUIDE.md`。那两份只保留长期约定和项目地图，用一句话链到本目录即可。

## 计划文件必须有的结构

每份 `docs/ai-plans/<slug>.md` 按下面顺序写。缺一块，后续 agent 就容易另起炉灶。

```markdown
# <短标题>

- 状态：`draft` | `active` | `paused` | `done` | `cancelled`
- 当前步骤：`S1`
- 创建日期：`YYYY-MM-DD`
- 相关讨论：一句话，不要贴长聊天

## 目标
## 非目标
## 锁定决策
## 进度总表
## 步骤
## 执行记录
```

### 字段怎么填

- **状态**
  - `draft`：还在写，禁止按其改业务代码。
  - `active`：按「当前步骤」执行。
  - `paused`：人为停，下一步仍从当前步骤继续。
  - `done`：全部步骤完成，只允许改执行记录或勘误。
  - `cancelled`：不再做；写清取消原因，文件保留。
- **当前步骤**：进度总表里第一个未勾选的步骤 ID，例如 `S3`。
- **目标**：做完后用户能感知到什么。写结果，不写过程。
- **非目标**：明确不做的事，防止范围膨胀。
- **锁定决策**：已经拍板、执行时不许再争论的技术/设计选择。后面对源码发现决策错了，先改计划里的决策再改代码，不要口头改。
- **进度总表**：所有步骤的一行清单，带 ID、标题、状态。
- **步骤**：每个步骤是一次对话默认的工作上限。
- **执行记录**：每做完一步追加一行，谁做的不重要，写日期、步骤 ID、结果、和计划有出入的地方。

### 单个步骤必须写清

每个 `S<n>` 包含：

1. **这一步完成的标志**（可勾选、可验收）。
2. **做哪些文件**（能列就列；列不全就写目录 + 匹配规则）。
3. **不要做什么**（本步禁止的顺手重构）。
4. **验收**：代码层面查什么；UI 是否留给用户看。
5. **版本**：本步若含用户可见代码，按 `docs/版本策略.md` 判断 major/minor/patch；纯内部收口可以暂不升版本，但要在步骤里写明「延后到哪一步一起记」。

步骤粒度：

- 一次对话能做完，且 review 时能看懂 diff。
- 不要把「全站所有页面换色」写成一步。
- 也不要细到「改一个 class 的一个属性」。

## 执行规则（goal 模式 / 按计划干活）

用户说「按计划做」「做下一步」「goal 模式继续 xxx」时：

1. 先读本规范，再读对应 `docs/ai-plans/<slug>.md`。
2. 只做 **当前步骤**。用户点名 `S<n>` 时才跳步；跳步不得顺手把中间步骤也做了。
3. 步骤里的「不要做什么」优先于「顺便把旁边也改了」。
4. 计划与当前源码冲突：以源码为准，并在同一次改动里回写计划（锁定决策或步骤说明）。
5. 做完一步：勾选进度总表、把「当前步骤」改成下一个未完成 ID、追加执行记录。还有下一步就把状态保持 `active`。
6. 最后一步做完：状态改为 `done`，并按该计划的收尾步骤更新 `AI_GUIDE.md` 等长期文档。
7. 发现必须拆步或合步：先改计划文件，再改代码，并在执行记录写原因。
8. 未完成的计划禁止另写一份平行计划；要换方案就改原文件的锁定决策。

## 和现有项目约定的关系

计划不能覆盖这些长期规则：

- `AGENTS.md`、`docs/版本策略.md`、`AI_GUIDE.md` 里的接口/布局/版本口径。
- 新增或实质重构的 Vue 单文件不超过 300 行。
- **纯换色、换 token、修主题接线，不算实质重构**，不要求顺手拆超 300 行的历史页面。只有同一任务里还改了职责结构，才拆文件。
- UI 实际效果由用户验收。除非用户在该任务里明确要求，否则不启动 `pnpm run dev` / `pnpm run preview`，不打开浏览器做视觉对比。
- 代码改动要跑 `pnpm run lint`、`pnpm run typecheck`、`pnpm run build`；纯计划文档改动可以不跑，回复里说明。
- 用户可见代码批次要同步版本和更新日志；纯计划/规范文档默认不升版本。
